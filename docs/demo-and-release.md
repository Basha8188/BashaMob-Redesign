# تشغيل الديمو وتسليم النظام

شغّل `demo.cmd` على Windows بعد تثبيت PHP 8.2+ مع pdo_sqlite، وتنفيذ `composer install` و`npm ci` و`npm run build` عند تجهيز نسخة التوزيع. لا يحتاج الديمو MySQL أو تشغيل Apache.

بيانات الدخول: `demo@bashamob.local` وكلمة المرور `Demo!2026Local`.

تُنسخ ملفات البرنامج إلى مجلد عشوائي داخل `%TEMP%\BashaMob-Demo`، وتُنشأ قاعدة SQLite جديدة بمستخدم إدارة وصلاحيات ومخزن وخزنة وعميل ومورد وثلاثة منتجات ومخزون تجريبي. ملفات البيئة وبيانات التشغيل والمرفقات الأصلية لا تُنسخ. تُعالج المهام فوراً، ويُكتب البريد في سجل تجريبي؛ خدمات WhatsApp والذكاء الاصطناعي الخارجية تحتاج مفاتيح خاصة وليست موصلة بحسابات النسخة الأساسية.

**أغلق نافذة BashaMob Demo لحذف بيانات التجربة وإيقاف السيرفر. إغلاق تبويب المتصفح وحده لا يُنهي التجربة.** تعمل مراقبة مستقلة لتنظيف المجلد عند إنهاء عملية التشغيل أيضاً. انقطاع الكهرباء أو إيقاف Windows قسرياً يمنع ضمان الحذف الفوري. الملفات التي يصدرها المستخدم خارج الديمو، مثل التنزيلات، لا تُحذف.

لفحص التشغيل دون فتح المتصفح: `demo.cmd -SmokeTest`.

## قبل التسليم الفعلي

- إعداد قاعدة MySQL/MariaDB منفصلة لكل عميل، وتشغيل `php artisan migrate --force`؛ لا تستخدم `migrate:fresh` على بيانات قائمة.
- ضبط `APP_ENV=production` و`APP_DEBUG=false` ومفتاح تطبيق خاص وعنوان الموقع وHTTPS.
- تعيين `OWNER_EMAIL` وكلمة مرور خاصة لا تقل عن 12 حرفاً قبل `php artisan db:seed --force`. إعادة البذر لا تغير كلمة مرور المستخدم الموجود.
- بناء الواجهة وإعداد `storage:link` وصلاحيات الكتابة ونسخ احتياطي للقاعدة والمرفقات واختبار استرجاعه.
- إعداد البريد وWhatsApp عند طلبهما، وتشغيل عامل Queue دائم للنسخة الفعلية.
- اختبار طابعة العميل والباركود وإجراء دورة بيع ومرتجع وصيانة على بيئة العميل؛ الاختبارات الآلية المحلية ليست بديلاً عن قبول العميل لهذه التجهيزات.

الديمو مخصص للتجربة المحلية. تسليم الكود التجاري لا يشمل تلقائياً استضافة أو مفاتيح خدمات خارجية أو ترخيصاً تعاقدياً.
